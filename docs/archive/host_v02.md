# Host v0.2：从过度 UNKNOWN 改成按实际故事判定

这次修改针对橡皮题旧局暴露的问题，不代表已经证明新 host 鲁棒。旧局保留四标签和原始短汤底；新版未复测模型。`prompts/archive/host_system_v0.1.txt` 与 `data/archive/host_examples_v0.1.json` 保存修改前版本。

## 为什么旧规则会失效

“没明确写反面，就不能 NO”在未知颜色等附带细节上合理，却让 host 不敢拒绝错误的核心解释。题目明明问这次为什么拿橡皮，host 却反复考虑是否还可能擦字、盖章。v0.2 限定问题默认指向这次事件及汤底的实际用途，对替代核心机制判 NO；对未交代的背景和具体实现仍保持 UNKNOWN。

同样需要承认旧版 prompt 是本项目自己写的，不能把所有问题归因于题目简短或 solver 能力。旧局第 6 问已经问到橡皮与铅笔是否相连；host 的 UNKNOWN 可能阻断了有用方向。但没有受控重跑，不能声称这一个回答就解释全部失败。

## 五标签约定

| 标签 | 适用范围 |
| --- | --- |
| YES | 事实、自然推论或完整解释得到支持；不要求逐字匹配 |
| NO | 事实被否定，或猜错了这次行为的用途、原因、机制 |
| YES_AND_NO | 组合猜测包含至少一个明确正确和一个明确错误的实质部分 |
| UNKNOWN | 真正未交代的信息；只有“正确 + 未知”也使用此标签 |
| CLARIFY | 不能判真假的请求，或语境无法消除且影响答案的歧义 |

单一因果命题“她因为下雨才拿伞取包吗”若实际原因是够不到包，应 NO，不能因为“拿了伞”这部分成立就 YES_AND_NO。组合猜测“她拿伞取了包，随后走出了房间吗”若取包成立、走出房间被否定，才是 YES_AND_NO。

UNKNOWN 也不能被完全消除。例如“笔尖是否折断”仍未交代：没有可用铅芯可能是用完，也可能另有原因。不得为减少 UNKNOWN 而擅自认定品牌、颜色、具体结构或心理动机。

## 参考答案的对齐与修订

用户粘贴内容开头有一个没有对应问题的 `no`。下面按“每个问题后面的标签是该问题的回答”对齐，这是一项记录假设，不是已确认的金标。

依据用户最后提供的完整解释：自动铅笔没有可用铅芯，橡皮盖住补芯口，取下橡皮、装入新铅芯，然后用铅笔写留言。

| # | 问题摘要 | 参考标签（按上述对齐） | 本次建议 | 判定理由 |
| --- | --- | --- | --- | --- |
| 1 | 拿起橡皮端使书写端露出或可接近？ | YES | NO（直接露出笔尖的理解） | 露出的是补芯口；如果 accessible 指补芯后间接可用，应先改写问题澄清范围 |
| 2 | 从容器抽出整支工具而露出书写端？ | NO | NO | 猜错整体机制 |
| 3 | 重力让书写端落下/展开？ | NO | NO | 猜错这里指定的重力伸出机制，不是在否定一切重力作用 |
| 4 | 橡皮相对笔身移动，且该动作直接露出笔尖？ | YES_AND_NO | YES_AND_NO | 两项明确断言：相对移动对，直接露笔尖错；若只问单一因果“取橡皮是否直接露笔尖”，则 NO |
| 5 | picked up 实际指取下橡皮而非拿起整支笔？ | YES | YES | 与完整解释一致 |
| 6 | 露出隐藏按钮/机构，再用它伸出笔尖？ | YES_AND_NO | CLARIFY | “机构”可能泛指补芯结构，也可能指直接出芯按钮；两者不同。不能把未交代按钮的存在自动当假 |
| 7 | 露出补芯开口，装芯后用铅笔写？ | YES | YES | 与汤底一致 |
| 8 | 自动铅笔、取下橡皮、补芯、写留言的完整解释？ | YES | YES | 不能因步骤多就 CLARIFY |

第 1、6 问保留措辞歧义记录，建议人工先改成“directly expose the writing tip”或“expose the lead-refill opening”再标注。不要为了得到预期问数而放宽成模糊 YES/YES_AND_NO。系统不输出参考记录中的 `Solved`：完整问题可以得到 YES，结束与最终评分由 controller/grader 管理。

## 已改的文件与验证边界

- `prompts/host_system.txt`：完整五标签协议，限定合理推断、错误机制排除、部分正确与歧义。
- `data/host_examples.json`：52 条示例；修订旧复合问题标签，新增与橡皮无关的取包故事；固定 `selection_order` 的前 8 条覆盖五标签及四个故事家族。
- `scripts/prepare.py`：识别五标签、检查选择顺序、按固定覆盖顺序构建消息。
- `data/host_dev/eraser_v02.json`：20 条开发审核题，保存原始短汤底、用户给出的完整解释、建议标签及原因；`human_label` 和 `model_label` 均为空。

橡皮故事仅进入开发审核集，不进入通用 few-shot；已有 20 道候选题和旧局记录没有改写。脚本检查只能确认五标签、样例选择和导出边界；新模型行为是否改善，需要另做重跑和故事不重叠的 host 评测。

后续 solver 必须同时收到新版五标签的含义。历史 run 的 solver 只知道四标签，不能直接恢复它并塞入 YES_AND_NO；应使用新会话并保存新 run。正式预算还应约束问题和组合猜测长度，防止把大量独立命题塞进一次查询。
