## CL：默认固定目标 B，共17个方向

每组首题是固定目标 B，positive/negative/neutral 成员只作为前题 A。
反向的 anchor→positive 仅用来探索其他发现，须显式指定 `--directions bidirectional`。
这些额外7个方向标记为 `analysis_role=exploratory`，不得混入默认主要比较。
用户的 irrelevant 关系在配置中写作 `neutral`，与 Host 的回答标签不同；关系标签仅为预设假说。

| Set | 固定 B | positive A | negative A | neutral A | 默认方向数 | repeat=3 的 B 局数 |
| --- | --- | --- | --- | --- | ---: | ---: |
| 1 | 13 | 15、16 | 14 | 28 | 4 | 36 |
| 2 | 34 | 35 | 33 | 12 | 3 | 27 |
| 3 | 22 | 47 | 45 | 19 | 3 | 27 |
| 4 | 7 | 26 | 21 | 31 | 3 | 27 |
| 5 | 38 | 46、32 | 45 | 28 | 4 | 36 |
| 合计 | 5个目标 | | | | 17 | 153 |

默认 `--source-policy fixed`：同一批次的每道 A **只解一次**，结束后揭晓其完整标准叙事，
冻结公开问答与答案。即使 A 未猜对，也保留实际失败轨迹并揭晓答案，不重跑直到成功。
随后同一 A 的所有 B 重复复用完全相同的经历；28、45 跨 Set 出现时也复用。
缓存仅限本批次，不自动使用旧实验文件；新输出批次会生成新的 A。
A 若 API 异常或需要审核，不替换成其他轨迹，依赖它的 block 停止或跳过。

每方向的每次 B 重复包括3个独立新会话：

1. `direct`：直接解 B，不提供 A。
2. `transcript`：解 B，提供固定 A 的公开问答和完整答案。
3. `answer_only`：解 B，只提供该 A 的汤面与相同完整答案。

每局独立100次提交预算，第100次强制最终提交。错误/不完整 final 占一次。
A 答案揭晓不计问题数，不给出评分 rubric、私有推理、关系标签或 B 的答案。
B 条件顺序随机并轮换，互不共享 B 的轨迹；每方向有自己的 direct 重复，不把同一 baseline 复制成多次观察。
`--repeat` 默认仍为3，指 B 条件的重复数，不代表固定模式下重新解 A 三次。

默认全部 CL：15个唯一 A + 153个 B = **168局**；单独 Set 1：4个 A + 36个 B = **40局**。
加上多 agent 60局，全部默认计划为228局。若开启双向探索：24个方向、20个唯一 A + 216个 B =236局 CL。
如需恢复 A 每个 block 都重新生成，显式指定 `--source-policy per-repeat`，作为单独实验报告。

固定 A 降低了前置经历的变化，但测到的是**给定这条 A 经历的 B 表现**。
不能把3次 B 当成3个独立 A 样本；跨 Set 共用 A 也有依赖。source_reuse.json、逐局记录和 contrasts
记录 `source_run_dir` 与 `source_context_sha256`，可核对经历一致性；源局成本只记录一次。
主要比较在同一个 anchor B 内进行，不能混合不同 B 的原始问数来解释正负迁移。

四种策略：`solo`、`solo_reflect`、`independent`、`shared_buffer`。
solo每次外部提交一次玩家调用；solo_reflect为同一模型提案/审查/修订三次调用；
independent为两名玩家独立提案再由leader选择原样候选，共三次调用。
shared_buffer两名玩家轮流提问，A关注身份/时序/主因，B关注反例/动机/遗漏链条。
每完成4次公开提交，在下一次请求时同步此前完整公开问答；同步前各自只看自己的新反馈，
另可见对方预约过的问题文本以避免重复，不能看到其未同步答案。最终强制提交前同步全部。
两人共用100次提交额度，不是各100。grader和Host不属于两个player。

所有模型请求彼此独立会话。Host/grader请求`gpt-6.1-sol`、player及默认partner请求`gpt-5.6-luna`，
Host/grader reasoning=high，player/partner reasoning=low，timeout600秒。使用当前Codex登录；不复制token或auth.json。
CLI未返回实际服务端模型ID，只能确认请求参数固定；这一限制保留在调用日志。
这里只更新配置，未调用模型验证当前账号的 gpt-5.6-luna 可用性；不会自动替换成其他型号。
Host启用独立复核，两次意见不一致时再裁定。四种公开回答不变。

## 一键命令

在仓库根目录运行。当前默认计划在 `runs/2026-11-02_fixed_source_plan/study_plan.json`，
含17方向、全部block、模型、复核分工及预计168+60局。旧 study_plan 目录是历史方案快照，不代表当前默认。仅计划不会花模型额度。

```sh
# 新目录生成计划，不调用模型（默认mode=plan）
python3 scripts/study_20261102.py --out runs/my_study_plan

# 待明确启动后：Set 1 固定 B=13，三类关系，B重复3次，40局
python3 scripts/study_20261102.py --suite continual --sets 1 --repeat 3 \
  --mode run --out runs/my_set1_pilot

# 可选双向探索：仍只写计划，不调用模型
python3 scripts/study_20261102.py --suite continual --sets 1 \
  --directions bidirectional --out runs/my_set1_exploratory_plan

# 新目录零调用演练，验证全调度及答案揭示/独立quota
python3 scripts/study_20261102.py --suite continual --sets 1 \
  --mode dry-run --out runs/my_set1_preflight

# 后续跑其余Set，不重复Set 1
python3 scripts/study_20261102.py --suite continual --sets 2,3,4,5 \
  --mode run --out runs/my_remaining_cl

# 多agent完整60局
python3 scripts/study_20261102.py --suite team --mode run --out runs/my_team

# 单个复核人的题目，例如Aurora的38题（12局）
python3 scripts/study_20261102.py --suite team --team-puzzles TS038 \
  --mode run --out runs/my_ts038_team
```

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--suite` | all | continual / team / all；all先CL后team |
| `--sets` | all | CL选1..5，逗号分隔；不会自动全排列 |
| `--team-puzzles` | TS038,TS002,TS014,TS022,TS042 | 指定五题的非重复子集 |
| `--repeat` | 3 | 各方向 B / 各策略重复次数；fixed 模式的 A 不重复，正整数 |
| `--directions` | primary | primary 固定每组首题为 B；bidirectional 额外加入7个反向 positive 探索方向 |
| `--source-policy` | fixed | fixed 每批每道 A 解一次后冻结复用；per-repeat 每个 block 重新解 A，不跨批缓存 |
| `--strategies` | solo,solo_reflect,independent,shared_buffer | team策略，必须含solo；支持原pipeline的其他合法策略 |
| `--sync-interval` | 4 | shared_buffer每N次已完成外部提交同步 |
| `--config` | configs/loop.codex.json | 模型配置；本研究强制Host=6.1-sol，额度=100 |
| `--dataset` | data/annotations/turtle50_v4/private.json | 题库JSON；绑定哈希必须匹配 |
| `--seed` | 20261102 | 只控制调度顺序，不控制模型随机采样 |
| `--mode` | plan | plan只冻结并列计划；dry-run零模型调用；run真实运行 |
| `--on-error` | stop | stop遇错误停止余下局；continue记录错误并继续独立条件，不能算失败分数 |
| `--out` | 必填 | 必须为新目录；拒绝覆盖，不支持隐式续跑 |
| `--help` | — | 显示帮助 |

每批冻结代码、prompt、全部题库、active包和模型配置至runtime_snapshot；
snapshot_hashes.json校验冻结内容。运行途中修改live Host不会污染同一批。
`status.json`记录launcher/child PID、状态和退出码。Ctrl-C可中断前台运行，已完成文件保留。
不得直接重跑同一目录；出错后修复并用新目录，按状态剔除无效API样本，而非按答题好坏筛选。

## 查看与分析

- `continual/index.html`或`team/index.html`可打开逐局HTML。
- `experiment_runs.csv`记录每局状态、是否成功、partial score、提问数、错误final及调用成本。
- `contrasts.csv`查看同方向/同重复的配对差异，结合来源A是否成功分层。
- 单局`trajectory.jsonl/md/html`及`human_review.csv`供复核；共享模式还有`shared_buffer.jsonl`。
- 首要报告成功率、最终partial score、100次预算内的总提交数；成功局问数另列，避免只看成功局造成选择偏差。
- 同时报告population/sample variance、样本量、模型调用/token/耗时；不能把共享单个A的多个B条件视为全独立来源样本。
- repeat=3是pilot，用于检查Host、异常和估算波动，不代表消除bias或有充分统计功效。
  正式扩样需先固定版本，再根据pilot方差与希望检测的效果确定重复数。

## Token 与费用记录（自动启用）

无需额外开关。下一次从当前代码创建的实验会记录每次调用的原始 usage、模型、角色、
输入 token（含缓存）、缓存读取/写入、输出 token、可取得的 reasoning token 和 USD 估算费用。
reasoning token 属于输出的细分，不再次加进总 token 或费用。
Host 初答/复核/裁定、grader、player、partner、memory 和所有已记录的失败重试均计入；
固定 A 的源局只计一次，其经历每次作为 B 的输入发送产生的 token 仍正常计费。

| 文件 | 内容 |
| --- | --- |
| 单局 `api_calls.jsonl` | 每个调用原始 usage 与 accounting；价格、价格快照哈希及未知原因 |
| 单局 `pricing_snapshot.json` | 本局冻结的价格表 |
| 单局 `token_costs.csv` | 逐调用 token 和费用，可直接筛选角色/模型 |
| 单局/批次 `cost_summary.json` | 总用量、按角色/模型汇总、已知费用小计、缺失费用/用量计数 |
| 批次 `costs_by_game.csv` | 每题/条件/重复的用量与费用，包含失败局 |

单局 trajectory HTML 和批次 index.html 均提供费用文件链接。批次汇总随逐局状态更新；
study 顶层在子批次结束或正常中断后合并 CL 和 team 的费用。
`known_estimated_cost_usd` 是有足够信息的调用小计；存在任意未知调用时，
`estimated_cost_usd` 保持 null。缺失 token 显示空值并计入 missing_token_calls，不能当作免费。
未升级的历史结果没有费用字段时，列入 games_missing_accounting，不自动冒充完整统计。

当前默认价格来自 2026-11-02 核对的官方 Standard 文本 API 价格，单位 USD / 百万 token：

| 模型 | 普通输入 | 缓存输入 | 缓存写入 | 输出 |
| --- | ---: | ---: | ---: | ---: |
| gpt-6.1-sol | 2.00 | 0.10 | 2.50 | 10.00 |
| gpt-5.6-luna（当前player） | 0.20 | 0.02 | 0.25 | 1.20 |
| gpt-6-luna（保留价格） | 0.10 | 0.01 | 0.125 | 0.50 |

来源：[GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol)、
[GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna)、
[GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna)。上述长上下文加价仅用于配置了该规则的 Sol/Luna：输入超过272,000 token时，
整次调用的输入/缓存单价乘2、输出单价乘1.5。缺少缓存明细时不猜缓存命中比例。

**这些数字是标准 API 等价成本，不是 Codex 账号实际扣费。**
`actual_billed_cost_usd` 保持 null；订阅额度、credits、折扣及税费以账号账单为准。
[官方说明](https://learn.chatgpt.com/docs/pricing)明确区分 API 单价和订阅用量。
Codex CLI 未返回实际模型 ID 时按请求 ID 估算，并记录 `model_basis=requested_unverified`。
非标准服务档位、未知模型、未配置价格的第三方接口不套用默认 OpenAI 费用。

默认表为 `turtle_loop/token_prices.json`。配置文件可添加顶层 `pricing` 对象覆盖整张表：
复制默认 JSON 的结构，按实际 provider/model 填入已确认的价格及来源（不填 key）。
该对象不发送给模型；启动时嵌入冻结配置。各字段：

- `schema_version=1`、`currency="USD"`；`checked_on` 为核价日期，`basis` 为估算说明。
- `models`：价格条目列表；每条 `providers` 为适用 provider 名称列表，`model` 必须精确匹配返回 ID（没有返回时用请求 ID）。
- `endpoint_prefix`：API 端点前缀，必须显式覆盖实际端点；Codex CLI 不使用此字段。
- `input_per_million`、`output_per_million`：非缓存输入和输出单价；缓存实际有用量时必须提供 `cached_input_per_million` / `cache_write_per_million`。
- `long_context_threshold`：可选长输入阈值；设置时必须同时填 `long_input_multiplier`、`long_output_multiplier`。
- `source`：价格来源。DeepSeek/Anthropic 用量格式已支持；未配置相应精确模型价格时仅统计 token，费用未知。

Anthropic 输入会加回单列的缓存读写用量；1小时缓存写入需要另行支持分档，目前费用标未知，避免套用普通写入价。
这些统计不改变问题数、评分、模型配置或实验暂停状态。旧冻结计划快照保留原版代码；要启用新统计，须从当前脚本创建新批次。
