# 固定 50 题的专属 host 资料与验收

目标是准确主持已知的 50 道题，不追求对未见题目的泛化。采用统一三标签规则、每题独立汤底/事实表和大量专属示例。每次游戏只加载当前题的资料包，重新开启上下文。

## 每题建立完整资料包

初始工作量建议每题 40–80 条人工确认的问答；这是规划数量，不是准确率保证，不应机械凑数。优先覆盖：

| 内容 | 建议数量 |
| --- | --- |
| 关键事实、机制与正确探索路径 | 10–15 |
| 常见错误解释及应否定的用途 | 10–20 |
| 同义改写、否定句、指代与时间范围 | 10–20 |
| 部分正确、直接/间接效果、动机/结果 | 5–10 |
| 信息不足、特殊边界与短多轮示例 | 5–15 |

每条包含 question、answer、局部 public_history、供审核者看的理由和审核状态。host 输出始终只有 `yes` / `no` / `yes and no`；理由不直接传给玩家。示例库中的同一句问题若在相同上下文下标签相反，应先修复资料再运行。

同一题的示例可以充分包含关键问题、完整正确解释以及预期错误方向。这些正是主持资料，不是给 solver 的提示。不得将资料包或 host 的输入挂载到 solver 的工具环境，也不能把 host 的专属知识当作 solver 的先验。

## 编写与审核

1. 固定完整汤底，写清动作、指代、动机、因果与未交代事项。
2. 用多条可能的提问路径扩展示例，不仅列作者自己的唯一解题路径。
3. 两位组员逐项审核标签，分歧裁决后再冻结。特别核对只改一个否定词、一个因果关系、一个主语时标签是否应变化。
4. 发现新的错误问法时，把裁决后的案例加入该题主持资料。同步修改汤底若需要解释原本不明的事实，并升级版本。

不要求 50 道题的示例相同，数量也可以不同；统一的是主持规则和质量标准。同一题在不同 solver 条件、重复实验中必须使用相同版本的资料包。

## 针对同一道题验收

先回放已经放入 prompt 的问答，检验是否忠实遵守资料。这是资料遵循度检查，不伪称独立准确率。

然后为同一道题另写一组未直接放进 prompt 的改写、否定、复合猜测和多轮对话。它们检验同一道题的实际问法覆盖，不是跨题泛化。若失败，可修复专属示例；修复后换一组新问法复验，不能只反复测试已经背下来的原句。

建议至少每题 10–20 条新问法和 2 条短多轮轨迹。记录总体准确率、各标签混淆、核心机制错答、同义改写一致性、上下文一致性、泄漏与格式错误。逐题报告，不用其他题的大量简单正确回答掩盖某题的关键错误。

正式运行前，已审核示例和关键路径检查应无未解决错误；普通问答的验收阈值由组员预先确定，例如 ≥98%。这是项目目标而非当前结果；少量检查全部通过也不证明所有未来问法都正确。对于低置信或有争议的 host 回答，实验外人工审核，修复后保留原局并按相同条件另开新局。

## 当前实现

- `data/host_packs/{puzzle_id}.json`：该题完整主持资料，带版本与审核状态。
- `python3 scripts/prepare.py host USER_ERASER_001`：52 条共享示例 + 该题全部专属示例。`--shots N` 只控制共享示例，不截断专属示例。
- 没有资料包的候选题暂时沿用候选 JSON；这不表示它已达到专属 host 的质量要求。
- `TARGET_DEMONSTRATIONS` 只带 question、answer 和局部 history；审核说明不会作为玩家输出。
- `read_host_packs()` 检查字段、标签、重复 ID 及相同问题/历史的冲突标签；它不能检查语义矛盾，仍需人工和模型验收。

目前仅接入橡皮题的 20 条待人工确认示例；尚未完成最终 50 题及每题 40–80 条问答，也未运行新版 host 实测。旧轨迹保留原样。所有正式 run 必须保存规则、当前题资料包、共享示例及模型设置的版本和哈希。
