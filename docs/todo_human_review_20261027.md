## 评分与实验设计需要人工签字的决定

1. **成功定义**：仍按完整叙事；core-mechanism recovery可另报，不能替换完整成功。核查最终提交是否明确承诺答案，而不是列多个互斥猜测。只评分本次提交还是累积对话要统一；当前不要偷偷将之前未复述的事实补入final。
2. **四标签边界**：主命题正确但有未知修饰、独立一真一未知、关键因果猜错、说话人/时点不明分别怎么处理。用具体正反例定标，不靠“多数内容yes”或一律mixed。
3. **CL题对**：G02可同时有course双关策略的正迁移和具体释义的负迁移，negative仅是假设。G07近答案复用是sanity check；另选机制相似但非重复答案的题对和弱关联对照。检查28组中重复有向题对，不能多次当独立证据。
4. **CL对照**：四种B保留；A/C无论解出与否，正常结束后揭示完整答案，运行错误则按manifest处理。控制C是否真正无关、是否跨block平衡、上下文长度是否匹配都需确定；目前只记录长度，并未严格匹配。
5. **双agent对照**：independent对solo_reflect匹配每步3次solver调用；shared_buffer对solo匹配每步1次。调用数相同不是token/计算量相同。先确定研究的是固定问数下效用，还是固定token下效用；两种结论不能互换。
6. **shared buffer**：两角度、交替提问、每4次完成提交同步（拟沿用）；同步前已有对方问题预约文本，因此不是完全隔离。审查实际收到什么、是否采纳、是否纠错、是否重复，不只统计交流发生次数。
7. **问数口径**：每局最多100次提交，第100次强制final；错误/不完整final占一次。成功final另记，当前`counted_questions`与`submissions`可能相差1。对外明确字段；100次未解出是预算耗尽，而非已知解题问数；错误和中断不填0。
8. **统计口径**：主指标最终partial score，另报完整成功率、预算消耗、成功局问数、token和耗时；best score只作补充。按同题/同重复编号比较各条件；报告完整配对数、缺失数和区间。多个问答轮次不是独立样本。

## 恢复实验后的建议顺序（当前不执行）

- [ ] 先完成下一批题目的P0审核，冻结dataset / rubric / Host packs / prompt / model / code版本和人工签字。
- [ ] 先做规则遵循回放，再做未放进prompt的新问法和多轮回放。可沿用旧规划：每题10–20条新问法＋2条短多轮作为初始工作量，但不是准确率保证。29条v7 fixture和88条历史fixture属于开发回归；已有few-shot原句不能充当独立测试。
- [ ] 人工先约定普通问答验收阈值及核心错答处理；核心未决错误不带入正式对比。报告逐题误差，不用大量简单正确例掩盖关键错答。
- [ ] 用冻结Host做完整小pilot。若继续沿用v7设计文档，可预先固定每条件12次作为pilot预算，以便平衡四条件顺序；12不是显著性保证，也不必一次扩到全50题。
- [ ] 根据配对差值的波动和事先认定有意义的最小效果确定正式样本量；不能因“现在不显著”无限加样，也不能只跑到结果好看就停。样本不足时明确报不确定。
- [ ] 扩展多题和A→B/B→A方向；先定题单，避免根据哪道题已出现合作收益再选题。维持版本一致，所有异常可追溯。
